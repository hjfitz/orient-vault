## What this is
Per-business delivery backends sit beside fulfilment backends in one `BACKEND_CONFIG` model, and orders reach whichever backends a business has. See [[Delivery Backends/Overview|Overview]] and the decision record [[config-service/decisions/2026-10-27-delivery-and-fulfilment-backends-share-one-backend-config-mo]].

**The invariant every unit holds:** no existing Snap consumer may see a non-SNAP backend before it has been upgraded to tolerate one. A Selector row that reaches a page parsed with the SNAP schema breaks Snap config for every business on that page.

## Risks
- **R1 ★ A Selector row breaks every Snap consumer** — the poller and snap-adapter parse whole `/api/v1/backend` pages with the SNAP-literal schema, and remote-config subscribers would nack-loop on an unknown type in a revision event. Mitigation: A2's `?type=` default of SNAP, then G1 before A3 — open.
- **R2 ★ The subscription swap stops Snap traffic** — if B3 lands before the deduper stamps `snap`, nothing reaches snap-adapter. Mitigation: G5, create-before-destroy, and the plan shared before apply — open.
- **R3 The deduper's config lookup becomes a dependency of every order** — B1 nacks on a failed lookup, so a config-service outage holds every order at the deduper rather than misrouting it. That's the intended trade. Mitigation: cache with a TTL so a short outage is absorbed — open.
- **R4 Credentials sprawl** — Selector credentials are stored in config-service Mongo the same way Snap credentials are. Mitigation: no logging of backend bodies (the spike's AC 6) — standing.

## Scar tissue
- **React 19 resets a form after a server action.** A failed submit must hand back what was typed (never the password) or the user loses their input. merak-portal's `actions.ts` does.
- **Next's route announcer is a `role="alert"`.** Scope test locators to the form.
- **Name the repo in an ilg-merak repo's `root.hcl`.** `basename(get_repo_root())` is `workspace` in CI, so a template-derived repo shares svc-template's state and its plans replace the template's services.
- **`gh` here prefers the env `GITHUB_TOKEN` PAT,** which isn't SSO-authorised for ilg-merak writes. Use `env -u GITHUB_TOKEN gh …` (the keyring OAuth token) for ilg-merak.
- **The backend backlink's `self` href is load-bearing.** wms-gateway (`internal/core/configrevision`) reads the businessId out of `{base}/backends/{businessId}` or `{base}/business/{businessId}/backend` with a regex. `/api/v1/backends/...` isn't a real route, but changing it silently stops wms-gateway invalidating its Snap cache. Found on A3, 2026-10-28.
- **A business ID can't be reused after delete** (409 "previously deleted"), so a live backend beside a tombstone of the same type can't happen through the API today. The unique index still puts `metadata.deletedAt` in the key.
- **`Collection.save` in config-service upserts on its filter.** A `backend_config` write filtered on `{ businessId }` alone overwrites whatever backend that business has. Every backend query and upsert carries a `type`, the requested one on the routes (A2, config-service#248).
- **Keep `BackendFragmentSchema` SNAP-only; add a union beside it, never widen it.** snap-adapter calls `.omit()` on it, which a union doesn't have.
- **The delivery/fulfilment classification lives in the portals.** config-service never decides which portal owns which type.
- **Selector never appears in fuse-ui.**
