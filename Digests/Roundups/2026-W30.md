# Fuse This Week — w/c 20 July (2026-W30)

## Posted text

*Fuse this week* — w/c 20 July

*🚀 Product progress*
• SFTP inbound files are now fully auto-organised — every file lands automatically in /archive once processed, or /error if something fails, and even files that fail before they can be read are now captured with a link back to the source instead of disappearing without a trace
• Return Goods Authorisation moved deeper into QA — return creation in the warehouse system is complete, confirmations now route to the correct connector, and two confirmation-output bugs found during testing have already been fixed
• Configurable CSV column ordering for confirmation files entered QA

*⚙️ Engineering*
• Closed out the platform's biggest in-flight migration: all sales/purchase order and master data creation now flows through the new shared create-record topics, every legacy topic deleted fleet-wide — and a live bug where a failed record's manual retry silently did nothing got fixed along the way
• Rolled out SecOps Workflows 0.2 across the fleet — unified security scanning, cleared two CVE waves, and re-scoped the nightly scan so it stops flagging false positives from unrelated branches
• Shipped automatic per-PR preview environments for the Fuse UI — spin-up, teardown, and nightly cleanup of orphaned environments, all automated

*📈 Reliability & operations*
• No new incidents this week. The carried-in duplicate-dispatch incident from two weeks ago is still being investigated — its postmortem and durable fix haven't moved
• The Fuse API gateway handled roughly 1,400 requests in production this week with zero recorded failures; the pipeline processed ~26% more records than last week
• A nightly automated alert for anomalous SNAP warehouse-system activity has now fired every night for five nights running without anyone investigating it — flagging it as a live gap, not (yet) a real incident
• Two customer-reported production defects — a cross-order data mixup and a batch-number mismatch in confirmations — were root-caused and fixed the same week they were reported; a separate bug that could silently drop confirmation/stock-adjustment rows under concurrent writes was also found and fixed

*💡 Highlights*
• *Matt Shaw* fixed a live production data-loss bug (concurrent writes silently clobbering a customer's confirmation files) the same day it was reported, and led the fleet-wide response to two separate CVE waves this week
• *Schuster Efigenio* diagnosed and shipped a fix for a customer-reported batch-number bug in confirmations — verified in dev and live in production within a day of the report
• *Harry Humby* root-caused a confirmation-routing bug that was sending Return Goods confirmations through the wrong connector mapping

*🤝 Cross-team & business*
• Unblocked another engineering team on a nightly pipeline that had been silently broken for days, and opened up direct lines of communication (plus a new escalation path) with business-side counterparts on integrations and Snap ownership
• Direct thanks and visible trust from the business side this week, including a transparent root-cause update on the STUBBLE order-mixup investigation

*🔭 Up next*
• Close out Return Goods Authorisation as a genuinely end-to-end flow — creation, confirmation, and file-based intake all converging through QA
• Decouple confirmation delivery from a customer's originating connector, so confirmations return only through the channel an order actually arrived on
• Begin scoping the next integration surface (Work Orders) and a reusable mapping-template library for operators

*📊 At a glance*
• 71 PRs merged
• 6 Jira items done, 36 progressed
• 0 new incidents
• ~1,400 API requests (instrumented gateway), 0 failures recorded
• ~5,160 records processed (↑26% vs prior week)
• 2 CVE waves cleared (17 PRs)
