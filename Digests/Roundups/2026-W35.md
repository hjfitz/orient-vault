# Fuse this week — w/c 24 August 2026

*Fuse this week* — w/c 24 August

_Morning team — a big push on Work Order confirmations and smart routing this week, plus a fair bit of quiet firefighting that never made the incident board. Nice work all round._

*🚀 Product progress*
• Work Order confirmations moved to the edge of feature-complete — every leg (API, config, collector, replay, UI) shipped this week bar SFTP delivery, which is back in for a fix.
• Smart, source-aware confirmation routing entered code review on the Snap side, with the SFTP and API consumers now being built to match.
• A full audit trail for configuration and connector changes shipped — every edit is now attributable to who made it and when.

*⚙️ Engineering*
• The Fuse MCP server — the team's internal platform knowledge/tooling service — completed its migration to Go, retiring the old Node service.
• Load-tested the order-ingest pipeline to peak volume and agreed a back-pressure contract, ahead of a major customer going live at high volume next week.
• A cross-repo sweep cleared several CVE waves across roughly a dozen services, keeping the dependency-audit gate green.

*📈 Reliability & operations*
• Zero incidents formally opened or closed this week — though a longer-running issue surfaced: one customer's Shopify order-retrieval window had been misconfigured for over a week, causing already-shipped orders to repeatedly re-push and get rejected; root-caused and corrected today.
• Prod availability held up well — the API gateway and Snap poller ran with no recorded failures this week; sftp-connector sat at 95.6%.
• Data-failure publish volume spiked in prod (~5x week over week); each spike has self-resolved within the alert window so far, but it's worth a proper look next week.

*💡 Highlights*
• Harry Humby fixed fapi's confirmation publishing to send one record at a time instead of bulk, stopping goods-in confirmations from silently stranding at the host interface.
• Schuster sourced RGA return-tracking numbers from Snap's attachment data, restoring carrier tracking on return confirmations that had always been blank.
• Matt enabled bulk order ingest for Purdy & Figg in production, clearing a key piece of infrastructure ahead of Tuesday's go-live.

*🤝 Cross-team & business*
• Cleared a stuck goods-out queue live for one customer's ops team and hardened the alert that should've caught it sooner.
• A big cross-team push getting Purdy & Figg ready for Tuesday's go-live — confirmation-delivery triage, retrieval-condition tuning, and live smoke-testing, including a sharp catch from their ops team on a form bug that fed straight into a fix.
• Saira Skin's migration has settled — quiet week, dashboards green.

*🔭 Up next*
• Close out Work Order confirmations end to end — the SFTP delivery leg is the one piece left before that epic is feature-complete.
• Extend source-aware confirmation routing out from Snap through the SFTP and API consumers.
• Support Purdy & Figg through go-live and hypercare from Tuesday.

*📊 At a glance*
• 30 PRs merged
• 18 Jira items done, 13 progressed
• 0 new incidents
• 1,926 API requests through the gateway (prod) — no failures recorded
• 4,615 records processed in prod (↓ ~20% vs last week)
• 3 CVE waves cleared across ~10 services

_Good luck to everyone supporting Purdy & Figg's go-live on Tuesday — the biggest new customer we're bringing on this year, and this week's prep shows it. Enjoy the long weekend, and see you refreshed on the other side 🎉_
