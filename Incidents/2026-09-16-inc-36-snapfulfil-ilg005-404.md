# SnapFulfil ilg005 returning 404 Not Found — sales order creation blocked

## Impact
From 2026-09-16 09:05 UTC, SnapFulfil's `ilg005liveapi.snapfulfil.net` tenant host returned a raw
IIS 404 Not Found page (not a JSON API error) for all requests, including `PUT /v2/shipments`
sales-order creation and even benign read calls. Four businesses share this host — PURDYFIGG,
STUBBLE, EPARFUM, WILDSMITH. 100+ sales-order creates failed between ~09:05–09:40 UTC. No data
loss: every failed create landed safely in replay-service's failure inbox (verified counts matched
exactly) and was retriable once the upgrade completed. Risk was fulfillment-cutoff delay, not lost
orders.

## Root cause
Not a vendor outage in the failure sense — it was a **planned SnapFulfil prod upgrade** on the
ilg005 tenant host, confirmed by ILG support after declaration. No advance notice was given ahead
of the maintenance window, which is why it was investigated and declared as an unplanned P1.
Confirmed not us: no snap-adapter prod deploy at onset (version unchanged), all affected businesses
share the same SnapFulfil host, and a live read-only SNAP call against the same host also 404'd.

## Resolution
Self-resolved once SnapFulfil's upgrade completed and the host started returning normal JSON
responses again. No platform fix required.

## Follow-ups
- Verify replay-service drains the ilg005 backlog once SnapFulfil's upgrade completes (spot-check
  clean redrive via `replay-retry`, confirm no order missed its same-day dueOut cutoff).
- Get ILG support/SnapFulfil to give advance notice of prod tenant-host maintenance windows — this
  was declared as an unplanned outage; a heads-up would avoid a full declare-and-diagnose cycle
  next time.
