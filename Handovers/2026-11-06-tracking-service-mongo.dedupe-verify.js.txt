phase('Investigate')
const results = await pipeline(
  LENSES,
  (l) => agent(l.prompt, { label: `investigate:${l.key}`, phase: 'Investigate', schema: FINDINGS }),
  async (r, l) => {
    if (!r) return null
    const toCheck = r.claims.filter(c => c.status !== 'holds' || c.severity === 'high')
    if (toCheck.length === 0) return { lens: l.key, result: r, verdicts: [] }
    const v = await agent(`${COMMON}

You are a SKEPTIC. Another reviewer made the claims below about tracking-service deduplication (lens: ${l.key}). For EACH claim, try to refute it by reading the code (or, for data claims, by checking how the numbers were derived; a re-query is fine, read-only). Default to "refuted" only with evidence; default to "unverified" when you cannot check.
- For a "holds" claim, look for a counterexample input that breaks the guarantee.
- For a "broken" or "risk" claim, check that the scenario really reproduces and isn't already prevented elsewhere.

Claims:
${JSON.stringify(toCheck, null, 1)}`, {
      label: `challenge:${l.key}`,
      phase: 'Challenge',
      schema: {
        type: 'object',
        properties: {
          verdicts: {
            type: 'array',
            items: {
              type: 'object',
              properties: {
                id: { type: 'string' },
                verdict: { type: 'string', enum: ['confirmed', 'refuted', 'unverified'] },
                reason: { type: 'string' },
              },
              required: ['id', 'verdict', 'reason'],
            },
          },
        },
        required: ['verdicts'],
      },
    })
    return { lens: l.key, result: r, verdicts: v ? v.verdicts : [] }
  },
)

const done = results.filter(Boolean)
const dropped = LENSES.map(l => l.key).filter(k => !done.find(d => d.lens === k))
if (dropped.length) log(`lenses with no result: ${dropped.join(', ')}`)

phase('Critic')
const critic = await agent(`${COMMON}

You are the COMPLETENESS CRITIC for a dedupe verification of tracking-service. Below are the findings and skeptic verdicts from five lenses. Don't repeat them. List only what was NOT checked that could still produce a duplicate record for a businessId + customer ref, or a double-counted event, during normal running or during the Mongo hard-cut migration. For example: a producer path no lens read, a store method that writes without the identity function (notes, refresh, backfills, redrive), concurrency between two first-creates, or clock and ordering assumptions. For each gap, give the file or path to read and why it matters. If you can check a gap cheaply, read-only, do so and say what you found. Be terse.

Findings:
${JSON.stringify(done, null, 1).slice(0, 60000)}`, { label: 'critic', phase: 'Critic' })

return { lenses: done, critic }
