## Intent
Move tracking-service persistence from Firestore (Native, db `tracking-service`) to MongoDB Atlas (Fuse house default), with no externally-visible behaviour change. Proof: in prod, ingest + serve from Mongo; PURDYFIGG 5-min reap bursts (~2k pushes/min) produce no store errors; /api/v1 parity with the Firestore-backed service; Firestore retired.
Motivation: 2026-11-06 09:10–09:16 UTC 536 commits RESOURCE_EXHAUSTED (gapic Commit auto-retry reuses dead txn id → surfaced InvalidArgument "transaction has expired"); hot counter docs (~40/s genuine-record cap from Oct load test); 27 composite indexes on shipments; transactional counters + recompute-stats; lane-filtered pagination workarounds.

## Planner's headline corrections to the proposed direction
1. "Unique event id + single-doc update" is NOT safe: reducer is order-independent but not redelivery-idempotent. `recordContentIn` (internal/core/dedupe.go:150-171) increments Copies on any already-seen hash, so a first-sighting message re-applied would be counted as a republished copy. Today only the event doc read+create in the same txn (firestore.go:364-370, 414) guards that. → Use Mongo multi-doc transactions, scoped to one record's own docs.
2. Counters → aggregation works because a record's contribution is derivable from stored state (`core.Contribution`, rebuild.go:37-51), but needs a narrow `marks` side-collection (recordJson up to 200 KB, events.go:11-13), and changes three served numbers (R1–R3).
3. Cutover via a shadow stack (second Mongo-backed Cloud Run service on its own Pub/Sub subscriptions, held during import), not a prod hold.

## Trade-offs (planner)
- Aggregate over marks; $merge materialise only if inc 6 measurements demand (est. 7d stats ~50–70k mark docs fine; 60d insights ~600k maybe needs $merge). Live $inc ruled out (non-idempotent outside txn; hot docs/WriteConflict inside).
- Transactions over CAS + appliedIds protocol; house precedent config-service mongo.unit-of-work.ts:30-34. Rule: txn touches only one record's docs (+ linked shipments for a return).
- Separate events collection (1000 × 200 KB breaks 16 MB; append-only).
- Shadow stack over dual-write (prod ingest exposure) and hold-and-cut (long hold, no live compare, lossy rollback).
- Dedicated M10 per service per env in shared Atlas project 686514b59feb171d628a10ef (config-service, replay-service, collector, shopify-connector, fuse-ui, secops, OMS). Flex only for disposable (fuse-mocker).
- recompute-stats keeps the rebuild half (refreshes marks), loses counter replace + ingest hold; backfill-* and redrive change only the opener; new import-mongo + parity.
